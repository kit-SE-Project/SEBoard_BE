# 비밀번호 재설정·변경 시 대여 로그인 무효화

작성일: 2026-11-13

## 적용 위치

- 기준: SEBoard_BE `codex/server-allday-integration`의 `2df48e2`.
- 전달 브랜치: `codex/server-allday-integration`.
- `AccountAppService.resetPassword`, `AccountAppService.changePassword`에서 기존 `AlldaySsoService.revokeAccount`를 호출한다.
- API 요청·응답 형식, DB 스키마, 프론트 코드를 바꿀 필요는 없다.

## 처리 순서

1. 이메일 인증 완료 여부 또는 현재 비밀번호를 확인한다.
2. 기존 DB 트랜잭션 안에서 비밀번호를 변경한다. 아직 최종 커밋하지 않는다.
3. 해당 계정의 Redis SSO 세대 값을 교체한다. 이전 세대에 발급된 모든 대여 grant와 미교환 일회용 코드는 사용할 수 없게 된다. 다른 계정에는 영향을 주지 않는다.
4. 폐기가 성공하면 DB 트랜잭션을 커밋하고 기존 성공 응답을 반환한다.
5. 대여 백엔드가 기존 grant를 다시 확인하면 SE 백엔드는 401을 반환한다. 대여 백엔드는 해당 로컬 세션을 제거한다.

대여 백엔드 `SeBoardAuthentication`에는 최대 30초의 계정·권한 캐시가 있다. 따라서 Redis 세대 교체는 즉시 이뤄지지만 기존 세션의 API 접근 차단은 캐시 만료 후 반영될 수 있다. 이 변경은 캐시를 강제로 비우는 별도 알림 기능을 추가하지 않는다.

## 실패 처리

- 이메일 인증이나 현재 비밀번호 검증에 실패하면 비밀번호와 대여 로그인 모두 유지한다.
- 비밀번호 저장 단계에서 실패하면 폐기를 호출하지 않는다.
- SSO가 활성화된 상태에서 Redis 폐기가 실패하면 예외를 그대로 전파한다. 기존 `@Transactional`이 비밀번호 변경을 롤백하므로 성공 응답을 주지 않는다.
- 폐기를 DB 커밋 이후 비동기로 실행하면 폐기 실패 시 비밀번호 변경을 되돌릴 수 없다. 이번 구현은 기존 트랜잭션 안에서 폐기를 완료한다.
- DB와 Redis는 분산 트랜잭션이 아니다. Redis 폐기 성공 뒤 DB 커밋이 실패하면 비밀번호는 그대로인데 대여 재인증이 필요할 수 있다. 이전 대여 권한이 남는 것보다 보수적인 결과다.
- 기존 SSO 비활성 설정에서는 `revokeAccount`가 아무 작업도 하지 않으므로 종전 비밀번호 재설정 기능은 유지된다.

## 범위와 운영상 의미

- 폐기 대상은 이미 발급된 대여 SSO 권한과 진행 중인 코드다. 계정의 모든 브라우저에 발급된 기존 대여 grant가 대상이다.
- 대여 예약 기록과 진행 중인 VM은 유지한다. 인증을 새로 완료한 뒤 기존 대여를 다시 조회한다.
- 기존 SE 게시판 access/refresh 토큰 전체를 폐기하는 기능은 포함하지 않는다. 게시판 로그인이 유효하면 통합 로그인 흐름에서 새 대여 grant가 발급될 수 있다. 비밀번호 유출 대응으로 모든 서비스에 강제 재로그인을 요구하려면 게시판 토큰 세대/폐기 정책도 별도로 적용해야 한다.
- 같은 refresh 토큰의 동시 갱신 문제는 별도 사항이며 이번 변경으로 해결되지 않는다.

## 검증

JDK 17.0.12와 저장소의 Gradle 7.6.1 wrapper를 사용한다.

```powershell
.\gradlew.bat test --tests com.seproject.allday.AlldaySsoControllerTest --tests com.seproject.allday.PasswordSsoRevocationTest --no-daemon --console=plain
```

기존 SSO 검사 5개와 신규 검사 8개가 모두 통과했다. 신규 검사는 실제 SSO 서비스와 Spring 트랜잭션 프록시를 사용하며 DB는 격리된 H2, Redis·계정 저장 서비스는 테스트 대역이다. 다음을 확인한다.

- 재설정 후 해당 계정의 복수 grant 및 미교환 코드가 401로 거절된다.
- 다른 계정의 grant는 유지되며 새로 인증한 grant는 사용할 수 있다.
- 로그인한 사용자의 비밀번호 변경에도 같은 폐기가 적용된다.
- 인증 확인 실패 시 비밀번호와 grant가 유지된다.
- 저장 실패 및 Redis 폐기 실패 시 실제 H2 변경이 롤백된다.
- SSO 비활성 환경에서는 기존 비밀번호 재설정이 가능하다.

실제 Redis·양쪽 백엔드·브라우저 왕복 검증은 별도로 필요하다. 테스트용 계정으로 기존 대여 세션을 만든 뒤 비밀번호를 재설정하고, 최대 30초 뒤 기존 세션 요청의 401 및 세션 제거를 확인한다. 이때 테스트용 DB·Redis를 사용한다.

이 변경은 전달 브랜치에만 반영한다. 운영 main 병합과 배포는 포함하지 않는다.
